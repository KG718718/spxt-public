# K⁺-SESSION 1.0 安装指南

版本1.0.0，Windows x64 在线安装。正式下载以该版本发布页为准；程序未提供代码签名。下载包只有经审查的程序、安装脚本和许可；没有公司名称、Logo、员工、供应商、客户、业务记录、账号密码、SMTP 配置或 OCR 模型。首次 Admin 由安装者创建。

## 1. 安装条件

使用受支持的 Windows 11 x64 或仍有安全更新支持的 Windows 10 x64，并具备系统自带 curl.exe、tar.exe、Windows PowerShell。云端已测试的具体系统以随包 report.json 为准，不能把服务器镜像测试等同于所有桌面版本测试。现代 Edge/Chrome 浏览器。

首次安装需要 HTTPS 访问 nodejs.org 和 registry.npmjs.org；Node 固定 24.21.0，归档和 node.exe 用 SHA256 校验，依赖按 package-lock.json 完整性安装。需要可写本地磁盘，建议预留 2 GB。网络下载失败可重新运行安装器，不会重置已有数据。

不要求预装 Node，不修改全局 PATH，不安装系统服务，不添加防火墙规则，不提升权限或放宽 TLS / PowerShell 策略。企业策略拦截时请管理员核对，不要关闭安全软件或绕过策略。校验和仅用于完整性核对，不等于数字签名或发布者身份认证。

## 2. 安装与启动

1. 从本项目已验证的 GitHub Actions 候选产物下载 ZIP，先核对 SHA256SUMS.txt。解压到独立目录。
2. 双击 Install.cmd，选择另一个本地目录，例如 D:\\K-SESSION。不要把实例装进解压包内，不要选择盘符根目录、共享盘、已有应用目录或不明非空目录。
3. 安装成功后进入所选目录，双击 Start.cmd。默认只绑定本机 127.0.0.1:8080；首次页面创建 Admin，无默认账号或默认密码。
4. 由 Admin 配置购买方、税率、服务费、奖金、账号、收款对象等。税率未填写不是 0%，系统不预置 6%。不要使用真实业务数据作为公开演示。
5. 保持服务窗口运行。停止时在窗口输入 stop 回车或 Ctrl+C，等提示退出后再备份/安装。关闭页面不会停止服务。

端口冲突时：在命令行运行 Start.cmd --port 8088。安装器不会停止其他占用端口的进程。

## 3. 数据位置与重复安装

程序：versions/<内容校验值>/app。官方 Node 和 npm：runtime。实例：instance，含 data.json、config.json、attachments、backups、邮件配置、运行日志及密文授权信息。安装代码不包含实例。

停止服务后重新运行 Install.cmd 并选原安装目录：同版本校验后保留，兼容的同数据结构新版本才切换 active.json，保留旧程序。依赖下载或校验失败不切换已激活版本，不改 instance。不同数据结构不能用本安装器强行升级，需另行审查迁移方案。

运行与安装共用 .lifecycle.lock，禁止并发安装或同实例双开。异常断电后若锁残留，先确认该安装目录的服务与安装进程均已结束，再仅手工移除这一目录的 .lifecycle.lock；不得直接删除数据或结束不明进程。

安装包内 .bootstrap-* 保存官方下载缓存，安装目录内 .staging-* 保存过程证据。安装成功并完成核验后可由安装者清理对应这一次缓存；不要删除 instance、runtime、versions 或未知目录。工具不自动清理历史版本和缓存。

## 4. 备份、恢复与回退

页面结构化数据备份只备份其注明的数据范围，不等于完整系统备份。完整恢复前先安全停止服务，把整个安装目录复制到独立备份目录并核对文件数量/校验值；包含 instance 的全部文件和对应程序版本。

恢复时复制完整备份到另一个独立目录，从恢复目录 Start.cmd 启动核对。不要在正在运行的实例上覆盖文件。回退应使用升级前的完整备份，不能仅切换旧程序却丢弃升级后新业务。没有备份时不要凭猜测修改 active.json。

SMTP 授权码使用 Windows 安全存储，跨 Windows 用户或异机恢复后可能需 Admin 重新录入。当前云端完整复制恢复测试不宣称异机密钥恢复成功。

## 5. 局域网、邮件、OCR

默认仅本机。确需局域网时才显式运行 Start.cmd --lan --port 8080，首个 Admin 仍须本机创建。由部署方另行核对专用网络、防火墙、主机地址、端口冲突及账号权限。安装器不开放路由器端口，不自动加规则。本候选没有完成两台真实设备的局域网验收，也不适合直接暴露公网；HTTP 局域网传输不等于 HTTPS 安全保障。

正式邮件默认关闭且无发件配置。测试发送也可能是真实测试邮件，应仅在 Admin 明确配置和点击后使用。云端验收不发送真实邮件。恢复后先检查发送开关和收件范围。

电子 PDF 优先文字解析。OCR 是可选增强，未配置时明确提示缺少引擎；参考下方可选 OCR 手工安装说明，在 instance/runtime/ocr/ocr-env 配置 Python 环境。Python/Paddle/模型不包含在本包，须核对其平台和原许可证，不能宣称离线 OCR 已打包。


### 可选 OCR 的手工安装

不使用 OCR 时可以跳过，本安装器仍能启动。需要 OCR 时，在部署者自己的 Windows 上安装官方 Python 3.11 x64；用该 Python 创建虚拟环境到安装目录的 `instance/runtime/ocr/ocr-env`。

停止服务后，在命令行用完整路径执行：

```text
"<Python 3.11 的安装路径>\python.exe" -m venv "<本系统安装目录>\instance\runtime\ocr\ocr-env"
"<本系统安装目录>\instance\runtime\ocr\ocr-env\Scripts\python.exe" -m pip install -r "<本系统安装目录>\versions\<active.json 中的 release>\app\tools\ocr\requirements.txt"
```

把尖括号部分替换为本机真实路径，不要照抄占位符。首次识别可能还需从引擎官方模型来源下载模型；参考对应上游的网络及许可证要求。本候选的合成识别证据仅覆盖已记录版本，不宣称任意扫描件或模型都准确。启动器始终使用实例中的上述环境和随当前版本保存的 OCR 脚本。

一般 SMTP 登录账号使用 Admin 配置的发件邮箱。如邮件提供商要求登录账号与发件地址不同，启动前可显式提供 `KSESSION_SMTP_USER`；授权码仍由 Admin 安全录入，不写进安装包。测试重置等开发开关不会被启动器继承。
