# K⁺-SESSION 1.0

**面向广告公司的 OA、财务核对和数据统计系统。**

适用于以项目为单位开展策划、活动执行和供应商协作的团队，把项目申请、费用审批、付款申请、发票核对、奖金和员工月结连接起来，让员工提交有入口、审批有依据、数据可追溯。

系统用于业务审批与财务核对，**不直接执行银行转账，不替代专业会计核算系统**。“付款审批通过”是系统审批结果，不等于银行已实际付款。

## 包含哪些功能

| 功能 | 可以做什么 |
| --- | --- |
| 项目申请与审批 | 填写甲方、活动日期、合同金额和费用明细，提交审批并查看项目及历史记录 |
| 付款申请 | 基于已通过项目申报实际费用、供应商和执行参与人员，核对项目预算与付款内容 |
| 欠款台账 | 申请、审批欠款，通过关联项目和付款核对归还情况、成本及余额 |
| 发票管理 | 上传发票、识别信息、检查购买方/销售方、号码及金额占用，审核、驳回、查看缺口和可用余票 |
| 奖金与执行费用 | 按 Admin 配置试算，由 Admin 确认；按权限查看本人业务奖金或执行费用 |
| 员工月结 | 按月份汇总已符合条件的奖金、执行费用和报销，保存可追溯的结算记录 |
| 甲方、供应商与收款对象 | 维护甲方、正式供应商、员工及公司收款对象，明确分类和关联关系 |
| 账号与权限 | Admin 创建和管理账号，区分员工、审批岗与 Admin 的可见内容及操作权限 |
| 邮件通知 | Admin 配置邮箱与发送规则，进行测试发送，查看通知和发送记录 |
| 数据统计与导出 | 按权限和筛选条件查看项目、付款、供应商、发票及月结数据，导出用于核对 |
| 备份与恢复 | 结构化数据备份，以及安装指南中的停机完整备份、恢复与升级前保护 |

电子 PDF 优先提取文字；图片、扫描件可选择配置 OCR。识别结果需要人工核对，OCR 不是必装组件。

## 谁来使用

- **员工**：提交本人业务，上传附件及发票，查看本人记录和结算。
- **审批岗**：处理获授权的审批事项，不能仅因有审批权限就访问全部管理配置。
- **Admin**：维护账号、主数据和业务参数，审核与核对，管理奖金、月结、统计及邮件。

角色权限以服务端校验为准，不只依赖页面隐藏按钮。

## 第一次安装

交付为**零业务数据**：不预置员工、客户、供应商、收款对象、项目、发票、附件、邮箱或共享密码。

1. 使用 Windows x64，首次安装须联网；无须预装 Node。
2. 解压在线安装包，双击 Install.cmd，选择独立的本地安装目录。
3. 安装完成后在安装目录双击 Start.cmd，从本机页面创建首个 Admin。
4. Admin 配置购买方全称、税率、服务费、奖金规则、账号与主数据。
5. 需要邮件或 OCR 时再单独配置；默认不会因为启动系统就向外发送业务邮件。

税率**不预置**，未填写不等于 0；未配置的业务参数会明确提示。安装、重装和升级不得清空已有实例数据。

完整步骤见 [安装、启动与备份恢复指南](tools/installer/README-install.md)。

## 安装目录与网络

程序、运行环境和 instance 数据目录相互分开。默认仅监听使用者本机的 127.0.0.1:8080；不会自动连接其他部署、发现网络中的系统、导入数据或同步账号。

同一电脑的端口已被其他服务占用时，使用 `Start.cmd --port 8088` 指定空闲端口，不覆盖或停止已有服务。需要局域网访问时才显式使用 --lan；部署方需另行核对网络权限、防火墙和传输安全。

当前验证来自 GitHub 托管 Windows 的独立合成环境；真实双机局域网尚未验收。不要直接把 HTTP 端口暴露到公网。系统不承诺多租户或多个进程共享写入同一实例。
