# K⁺-SESSION

项目审批、付款申请、欠款台账、发票核对、奖金与月结、统计导出的独立公开候选。

**完整运行服务和五个页面已接通并通过托管 Windows 合成验收；仍不是正式发布的“一键安装包”。** 所有当前代码位于 [codex/public-v1](https://github.com/KG718718/spxt-public/tree/codex/public-v1)，main 尚未合并。准确进度和未完成项见 [PROJECT.md](PROJECT.md)。

## 新安装原则

- 不带用户、供应商、收款对象、客户、项目、付款、欠款、发票、奖金/月结、附件或历史配置；测试夹具不进入程序包。
- 安装者在主机本机创建首个 Admin，没有共享默认密码。随后由 Admin 创建账号和关联主数据。
- 购买方全称、税率、服务费率和奖金规则由 Admin 明确配置。未配置不暗中套用公司数值；明确的 0 与未填写不同。
- 员工替票由 Admin 显式授权。员工收款对象关联不等于替票授权，历史分类和保存快照不因授权变化改写。
- 原单位的专属收款对象机制已移除，不将特例转授全部公司收款对象。欠款成本仅接受有效正式供应商。
- 升级、重启及初始化失败不得清空现有实例。已有数据/配置损坏或关键结构非法时拒绝启动，不自动生成空库。

## 当前可验证范围

- 实际服务的初始化、登录、实时权限、配置原子保存、上传与下载、发票校验和跨模块业务链。
- Admin、员工、审批岗的真实浏览器操作；默认、悬停、焦点、弹窗和表格可读性；截图只包含明确合成数据。
- 项目→付款→发票→奖金/月结，欠款比例成本、导出授权、正式邮件关闭与测试传输隔离。
- 可选 OCR 已分别验证缺组件提示、解析器，以及云端安装后的合成图片实际识别。识别结果仍须人工核对，不保证任意版式准确。
- 核心程序 ZIP 的白名单、逐文件 SHA-256、无业务资产、解包初始化、重启和程序替换保留数据。程序包不包含测试或截图。

最新测试、证据和纠错记录：[整站与封装验收](docs/tasks/public-v1/batch-15-workflow-and-core-package.md)。

## 下载物边界

Actions 中的 **application-core-only-not-installer** 是核心程序档案，包含清单与校验值，**不含 Node、npm 依赖、Python/OCR 引擎或模型，不能当作独立安装器双击使用**。哈希用于完整性核对，不等同于签名或对不可信来源的安全担保。

当前不提供生产部署教程，不建议将候选用于真实业务。完整安装方式尚待确定：原生图形二进制的全部随附声明没有核验完；已提出首次联网从官方来源安装锁定运行依赖的替代方案，尚未得到选择，未自行实施该分发方式。

## 支持与未验收范围

当前证据来自 GitHub 托管 Windows 及本机回环地址。真实双机局域网、网络加密/防火墙、任意旧版本迁移、服务安装和最终独立发行包均未验收。不要将端口直接暴露到互联网；不承诺 SaaS、多租户或其他平台。结构化数据备份仅包含 data.json，不等于完整实例备份。
