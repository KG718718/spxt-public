状态日期：2026-09-11。全部数据为 GitHub 托管 Windows 内明确虚构的夹具，不是任何真实业务记录；开发机未保存公开副本、运行实例或包。

## 本轮真实修复

1. 项目审批列表/详情及付款重编辑的三处显示错误使用当前税率。隔离项目以税率 0.02 保存后，Admin 将当前配置改为 0.05，旧项目页面曾显示新值。修复后按已保存 taxAmount / 项目快照读取，不改历史金额；实际浏览器看到合同 1000、成本 300、合同税费 19.61、利润 680.39，付款继续一致。
2. OCR 单张入口在识别引擎之前补齐项目归属复核；其他员工的项目返回 403，不创建业务事实。组件缺失返回明确 503；失败时清理本请求文件，不泄露内部路径。
3. 项目/付款审核“详情、通过”等按钮默认与悬停颜色冲突。修复为金底深字，黑底按钮浅字；实际非空表格、详情、焦点与悬停再次核验。未增加审批能力或改变业务按钮条件。

## 测试契约校正，不作为生产缺陷

- 普通已确认供应商付款行不强制携带 pending-confirmation 来源明细ID；测试按实际页面构造。
- 普通发票应补在当前服务读取付款明细 amount；服务费仍参与相应财务计算。本轮未改变发票金额公式。隔离付款普通明细 400+100，发票应补 500。
- 奖金预览使用 preview.projectRows；月结实际导出仍通过既有 module=bonus。
- 模板测试是测试收件人的 SMTP 发送路径，不等于 dry-run。本轮仅使用已有限定条件的虚构捕获传输，不连接真实邮件服务；正式发送关闭，测试不改正式发送台账。
- 上传归档后用持久化 attachment.path 下载，而不是已经归档的临时路径。
- 甲方创建权威字段是 fullName，不新增 name 别名。

## 核心程序档案

tools/package-manifest.json 按允许清单收32份运行文件。包含项目 MIT、第三方说明和依赖锁文件，不含 Node/npm依赖/Python/模型、测试脚本或夹具、任何实例、配置、附件、备份、日志、截图。

云端生成 application-core-only-not-installer，内有ZIP、逐文件清单、SHA256SUMS和报告。程序文件及计数/名称/校验值不符或额外 data.json 均拒绝核验。相同输入重复构建字节一致。校验和仅供完整性比较，不是签名；不能据此信任未知分发者修改后重算的包。

解包后使用 runner 已安装的 Node 和锁定依赖，真实启动/创建Admin；这证明解包程序可运行，**不是包自带完整运行环境**。同版本程序替换不包含任何实例文件；不冒充任意旧版升级或结构迁移通过。

完整实例恢复使用停止服务后的合成实例副本，恢复到新隔离目录，核对原件/备份/恢复副本的逐文件SHA256、配置、账号、主数据及附件，随后实际登录读取。是受控恢复演练，不是新增通用自动恢复入口；没有覆盖原实例。
