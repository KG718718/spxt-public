## 阶段三：适配与失败优先测试

- 首Admin初始化：首次成功、重复拒绝、非本机拒绝、无默认密码、损坏数据不覆盖。
- 零业务数据验收：解包后无预置身份、供应商/收款对象或业务文件；首次启动不注入种子。创建首Admin前账号为0，完成后只产生用户创建的Admin及必要初始化审计，主数据/业务记录仍为0；再以隔离虚构数据验证用户自行建账号/主数据和关联的流程。
- 将升级/重启的数据保留与新安装空库分开测试；带有虚构旧业务的升级样本必须原样保留，不调用清空脚本，也不把验收后的数据目录打入最终包。
- 购买方：Admin配置自己的单位全称；未配置/名称不匹配拒绝、匹配时仍执行其他既有发票校验、员工越权配置拒绝、直接payload不能绕过。不得把购买方匹配等同于自动审核通过。
- 员工替票授权方案已获有条件确认；整份Plan批准进入实现后，验证新账号默认未授权、Admin从有效账号列表勾选、员工/审批岗越权维护拒绝、仅关联收款对象不授予资格、授权员工处理正常替票、正式供应商销售方不匹配仍拒绝。
- 授权撤销/账号停用后旧草稿递交重新校验，直接payload和身份近似名称不能绕过；已确认发票、原金额、收款类型和池归属不被授权更改。不得将操作权限名单复用于动态重分类历史。
- 公司专属收款机制已确认移除：不新增替代映射。先固定原特例在银行信息和欠款前后端筛选中的反例，再移除专属身份/授权、欠款准入及银行字段豁免；验证正式供应商正常可选，员工和其他公司收款对象不因删除条件而获得新的欠款资格，空态/文案与服务端一致。保留通用收款类型及其他既有业务规则；不修改来源公司系统。该项实现仍须整份Plan批准。
- 员工替票兼容性门禁：用虚构账号及等价授权输入对照原业务判断，项目可见性、角色权限、供应商校验、占用/余额、历史快照和金额结果不得发生未批准变化；发现差异先固定反例并返回确认。以上均为待执行计划，不是实现或回归通过结果。
- 奖金：无公司历史算例残留、配置缺失明确提示、原普通计算回归。
- 邮件：测试与正式状态隔离、默认不发送、安装者自配、收件角色落地页权限正确。
- 不将运行代码复制到公开库后才清理敏感信息。
