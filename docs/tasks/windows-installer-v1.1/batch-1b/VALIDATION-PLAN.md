# Batch 1B — Runtime Validation Plan

状态：只设计验证方法，以下 Runtime/机器/页面用例均未执行。不得把本文件的检查计划当成测试通过记录。

## 1. 两层验证，避免阶段循环

### G1 — Runtime 闭包验证（未来 Runtime 实施完成后、Batch 2 集成前）

此时还没有正式 Launcher。由测试专用 harness（不进入产品包）以包内 node.exe、app/server.js、明确 cwd 和现有 KSESSION_* 路径接口启动应用，确认实际后端就绪，再由验证人员或外部测试工具打开系统浏览器。

这只证明 Runtime 能被正确消费者离线启动，不冒充普通用户已能双击、已有桌面快捷方式或正式 Launcher 自动打开页面。测试 harness 不是交付给用户的命令行安装步骤，本轮也不创建 harness。

### G2 — 最终入口集成验证（Batch 2/3 后及 Batch 6）

正式 Launcher → 包内 Node → server ready → 自动打开默认浏览器 → 首次 Admin → 登录 → PDF 文本处理 → 上传 → Excel 导出 → 备份恢复。此层验证界面失败反馈、无常驻 CMD、重复启动、退出/停机；Setup 和快捷方式还需 Batch 3/6。

不得因 G2 依赖未实现 Launcher 而无限循环阻止 G1；也不得用 G1 的开发测试入口替代 G2 产品入口。

## 2. Windows 11 x64 干净目标机

- 使用已批准的干净快照/测试机，记录 Windows 版本、构建号、x64、系统补丁、默认浏览器与测试账户类型；没有预装 Node/npm/Python/Git/开发工具，没有 npm/OCR 模型缓存。
- 普通 Windows 用户运行，初始 Node/npm/Python/Git 发现检查应无可用外部工具；保留系统必要 PATH，不从构建机复制用户配置。测试工具带来的隐藏 runtime 不能进入被测进程搜索路径。
- 干净机允许已有 OS 系统库，但必须记录 VC/UCRT 等状态；不能在有开发环境的 runner 上运行后声称普通 Windows 无依赖。
- **阻断外部网络，保留回环 127.0.0.1/必要 localhost**。彻底阻断回环会使浏览器无法访问 Node，并不检验离线闭包。禁止 DNS/代理/外部 CDN/npm/Node 下载回退；策略和流量日志只在隔离测试机采集，不修改开发或运行主机网络。
- 将候选 Runtime artifact 作为输入传入独立测试位置，先核对外置校验和、可信构建身份和包内清单。
- Runtime 目录保持只读使用，实例、上传、导出、备份、临时文件和测试证据使用包外独立可写目录。验证中文、空格路径和非管理员权限，不包含真实数据。
- 浏览器测试工具/合成夹具在包外，不能隐含提供缺失依赖。网络监控区分浏览器自身 OS 后台流量与应用依赖请求；所有外部访问均被阻断，不能给应用加联网例外使测试通过。

Windows 10 x64 受维护版本继续属于正式支持目标，具体矩阵待确认；只在 Windows 11 通过不代表 Windows 10 已验收。ARM/32-bit/旧系统不纳入本阶段承诺。

## 3. G1 核心用例与判定

| ID | 场景/动作 | 通过证据 | 失败判定 |
| --- | --- | --- | --- |
| V01 | 冷态清单核对 | Node、app、依赖、资源、许可与 manifest 文件集合/哈希完全一致 | 缺件、多件、版本/平台不符 |
| V02 | 包内 Node 与原生加载 | 实际 Node 版本/arch/模块解析位置都来自候选包；canvas真实操作 | 借用系统或测试工具依赖、DLL缺失 |
| V03 | 隔离启动与就绪 | 外置 harness 启动指定进程；确认端口归属、进程存活和登录/初始化页面可用 | 日志出现 ready 但服务不可用、连接到其他程序、启动改写程序包 |
| V04 | 新安装零数据与首次 Admin | 包中无 data/config；浏览器原有初始化页面由验证人员创建纯合成 Admin；再次初始化拒绝 | 预置账号、共享密码、覆盖残留数据 |
| V05 | 登录与重启 | 原流程登录、停止指定实例、重启后相同合成账号/配置正常；首次入口保持关闭 | 重启清空/改写既有实例、不相关进程被结束 |
| V06 | 文本 PDF | 使用外置明确合成的中文/多页/字体样本，经现有页面/接口调用实际解析；不配置 Python | 依赖 OCR 才能识别普通文本层、资源/字段错误、网络下载 |
| V07 | 文件上传/下载 | 原有合成业务流程形成合法上下文，上传中文命名文件；重启后下载字节一致 | 乱码新文件名、附件不持久、权限漏检 |
| V08 | Excel 导出 | 经现有权限和页面入口导出；XLSX结构/内容/中文/金额校验；测试解析器外置 | 依赖安装 Excel/Office 才能生成，或越权数据出现 |
| V09 | 结构化数据备份 | 原有 Admin 备份入口产出与其声明范围一致的合成数据备份与校验 | 把仅 data 备份宣称为包含附件/密文的整机备份 |
| V10 | 停机完整副本恢复 | 在测试控制端安全停止，记录 instance+对应Runtime全文件哈希，恢复到新隔离位置；同一Windows身份登录/附件/配置一致 | 在运行实例上覆盖、丢失附件、改写源实例、恢复后发送邮件 |
| V11 | 不可用 OCR | 不配置 Python/模型时原页面明确提示引擎缺失，不静默下载或伪识别成功 | 将 OCR 缺失变为成功识别，或核心因此无法启动 |
| V12 | 全程离线 | 外部网络阻断、无依赖下载请求成功、核心全流程完成；程序包验证前后哈希相同 | 需开放外网才成功、依赖缓存假阳性、测试数据进入包 |

已有公开 tools/installer/README-install.md:33–39 与 tools/tests/online-installation.js:151–155 区分“页面结构化数据备份”和“停机完整目录副本恢复”。本计划沿用该事实：V10 由测试控制端操作，不虚构现有 UI 全量恢复按钮，不新增恢复业务功能。最终普通用户的升级/恢复体验由 Batch 4 单独设计，不能把测试人员文件操作写进“一键安装”用户要求。

财务/配置必要输入全部通过现有 UI/API 录入明确合成值，无测试默认税率或内置账号进入发行包。真实邮件投递、OCR引擎识别、LAN双机、跨Windows身份DPAPI恢复不属于 G1 核心离线通过范围。

## 4. 失败优先与破坏性反例（仅针对独立合成副本）

| 反例 | 预期 |
| --- | --- |
| 删除/篡改 Node、某个生产包、.node、PDF资源或许可证 | 验证拒绝，指出具体组件；不联网修复 |
| 加入额外文件、路径穿越/重解析点、大小写冲突、错误架构 | 取件或清单阶段拒绝，不能逃出 staging |
| 放入实例数据、SMTP配置、npmrc、测试Admin或非公开地址 | 打包门禁失败，不上传 artifact |
| npm exit=0 但 Windows 平台 optional 未安装 | 生产图核对/真实加载失败，不标为可选跳过 |
| lock 与实际包版本不符/缺 integrity/依赖版本浮动 | 拒绝，不执行 npm update 或改 lock |
| 污染 NODE_PATH/NODE_OPTIONS/系统存在其他 Node | 被测启动仍使用指定包、控制环境；无外部替代加载 |
| 实例目录只读、已有损坏数据或残留资产无主数据 | 明确失败，原目录逐字节不变，不重置为新安装 |
| 端口占用、第二次启动、测试中断 | 不抢杀其他进程；记录归属，停止自己创建的实例；Launcher用户行为待G2 |
| 校验和文件与manifest被一起替换 | 本地自洽不足以通过；可信外部artifact身份/校验来源必须不匹配并拒绝 |

## 5. 证据与退出

每次记录 source commit/tree、Runtime ZIP hash、manifest hash、Node/npm、OS build、浏览器版本、账户权限、网络策略、每项结果/异常、原生加载清单、包前后校验和、合成截图与日志。报告放在独立 evidence artifact，不装进 Runtime，不记录密码、会话、真实内容或完整用户机器环境。

所有进程按本次创建的身份/路径/PID核对停止，不按名称批量杀 Node。数据清理只针对预先确认的测试目录，未授权清理则保留并登记；不能清理源码、运行实例或原发行物。
